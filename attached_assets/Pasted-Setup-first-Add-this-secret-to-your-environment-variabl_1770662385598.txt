Feature: Live Price Recalculation

When a user changes their company parameters (employees, vehicles, or risk_level) on the registration/settings form, we need to call the Landing Page API to get an updated, signed price.

Step 1: Backend Route — POST /api/update-quote

Create this endpoint. It acts as a proxy + validator:

Receive from the frontend: { employees, vehicles, risk_level, company_name, coupon_code? }
Call POST https://sst-colombia.com.co/api/recalculate with that same JSON body.
The response is { "token": "eyJh..." }.
Verify the token signature using process.env.JWT_RECALCULATE_SECRET (HS256 algorithm). If verification fails, reject the request.
Decode the verified token. The payload structure is:
{
  "sub_data": {
    "base_monthly_price": 316000,
    "current_period_price": 284400,
    "discount_duration_months": 1,
    "currency": "COP"
  },
  "metadata": {
    "company_name": "Mi Empresa SAS",
    "employees": 10,
    "risk_level": "I",
    "vehicles": 0,
    "coupon": {
      "code": "A23MGSSG",
      "discount_type": "percentage",
      "discount_value": 10,
      "discount_amount": 31600,
      "duration_months": 1,
      "first_month_only": false,
      "coupon_type": "primera_compra"
    }
  },
  "iat": 1770662033,
  "exp": 1770663833
}
Note: metadata.coupon is null when no coupon was applied. When there's no coupon, current_period_price equals base_monthly_price and discount_duration_months is 0.

Save the verified data to the database: update the company/subscription record with the new employees, vehicles, risk_level, base_monthly_price, current_period_price, and the raw token string.
Return the decoded sub_data to the frontend so it can update the displayed price.
Step 2: Frontend

Add event listeners (change event) to the employees, vehicles, and risk_level inputs. When any value changes:

Send a POST to our own /api/update-quote with the current form values.
The response contains sub_data — use sub_data.base_monthly_price and sub_data.current_period_price to update the price display.
IMPORTANT: Never decode or trust the JWT on the frontend. All verification happens server-side.
Security notes:

The token expires after 30 minutes. If expired, request a new one.
All prices are integers in COP (no decimals).
The main page must NEVER recalculate prices itself. It trusts current_period_price as the "agreed price" from the landing page.
This way the main page agent has everything needed — the secret, the exact payload structure, and the correct security flow where the backend verifies the token before trusting it.
